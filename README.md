# Расписание УТЖТ

Сайт: **https://raspisanie-utgt.github.io/**

Статический сайт: расписание любой из 19 групп очного отделения на сегодня, завтра и неделю
с реальным временем звонков, с учётом замен и с картинкой распоряжения о замене.
При первом заходе открывается выбор группы, выбор запоминается; ссылка `?group=21-С` открывает
нужную группу сразу. «Я преподаватель» — расписание преподавателя по всем группам (`?teacher=`).

## Откуда данные

| Файл | Источник |
|---|---|
| `data/groups/*.json` | [Расписание учебных занятий, 1 семестр 2026/2027](https://utgt-pgups.ru/raspisaniya-i-grafiki.html) (PDF), все 19 групп — `tools/extract_schedule.py`, сверены вручную |
| `data/calendar.json` | Календарный учебный график: каникулы, практики, сессии, праздники — `tools/extract_calendar.py` |
| `data/bells.json` | [Расписание звонков 2026/2027](https://utgt-pgups.ru/raspisaniya-i-grafiki.html) (PDF) |
| `data/zameny/` | [Замена уроков](https://utgt-pgups.ru/ochnoe-zaochnoe-otdelenie/58-zamena-zanyatij.html), обновляет `scraper.py` |

**Недели.** Расписание чередуется: 1-я / 2-я неделя. В PDF это ячейка, разделённая на две строки:
верхняя — 1-я неделя, нижняя — 2-я, предмет идёт на всю пару (у 11-А: пятница и суббота, 3-я пара).
Номер недели считается от `week_anchor` в расписании группы (19.10.2026 — 1-я неделя),
а если в распоряжении о замене написано «N-я неделя», берётся оттуда.

## Как это работает

1. `scraper.py` скачивает страницу замен, находит блоки «на DD месяца YYYY года / очное отделение»
   и скачивает картинки.
2. Замены публикуются **картинкой**, поэтому скрипт ищет сетку таблицы и распознаёт каждую ячейку
   через tesseract (русский). Строки всех групп сохраняются в `data/zameny/<дата>.json`.
   Если распознавание сомнительное, сайт об этом предупреждает. Картинка показывается всегда.
   Картинки бывают мелкими (≈620 точек в ширину) — тогда tesseract путает П/Д/И, 7/1, 3/5. Поэтому группу,
   урок и кабинет читаем несколькими способами (разный масштаб, белое поле вокруг, «только цифры»)
   и берём ответ большинства; потом сверяем с расписанием (`check_with_schedule`: отмена урока, которого
   у группы нет, — неуверенно; спорный кабинет — по расписанию и прошлым распоряжениям).
   Расхождение прочтений (меньше 60% согласны), кривая группа (на весь её блок), ячейка с текстом,
   прочитанная пустой, урок вроде «1-5» — строка помечается «неуверенно», и сайт просит сверить с картинкой.
   После правок распознавания: `python tools/ocr_proverka.py` — сравнит со всеми сохранёнными днями;
   `python tools/ocr_sintetika.py` — нарисует таблицы «как распоряжение» и проверит, что ни одна ошибка
   не проходит без пометки (на 1400 строках: ошибок ~3%, все помечены, лишних тревог ~3%).
3. `site/agenda.js` в браузере накладывает замены на обычное расписание и звонки
   и подсвечивает текущий и следующий урок (время московское). Дни выбираются полосой «Пн 2 · Вт 3 …»
   (две недели без воскресений и «Неделя», на телефоне листается вбок и свайпом по расписанию); у предметов
   свой цвет; идущую пару обходит рамка-таймер; до первой пары и на перемене сверху крупно следующая пара;
   «Поделиться» под парами делает картинку дня (`shareCanvas` в `app.js`).
4. GitHub Actions (`.github/workflows/update.yml`) запускается каждый час с 06:47 до 21:47 МСК
   (и сразу по сигналу сторожа `tools/storozh.gs`), сохраняет новые замены коммитом и деплоит сайт на GitHub Pages.
   Тесты в нём идут только при правках кода (push) — ежечасное обновление их не ждёт и не может ими остановиться;
   тесты читают только образцы из `tests/fixtures`, а не живые `data/` (там дни старше 21 дня удаляются).
   Любая поломка — задача с меткой `сбой` (`tools/health.py`); на сайте — плашка «данные не обновлялись с …».

Замены обычно выкладывают **накануне**, поэтому сайт хранит их за последние 21 день,
и «сегодняшние» замены остаются видны, даже когда на сайте УТЖТ уже висят завтрашние.

## Локально

### Ручная проверка фотографий из ВК

Наличие замен за ту же дату на сайте не означает, что новое фото из ВК проверено.
Ответ «уже опубликовано» допустим только для чистых сохранённых данных и совпадающего
изображения (SHA-1). Иное фото за ту же дату требует проверки: это может быть исправление
или дополнение. Сомнительные сохранённые данные также не считаются проверенными.
Загрузчик официального источника сохраняет изображения и отметки сомнений; обработчик ВК
не заменяет эти данные неподтверждённым распознаванием. Бот отдельно сообщает о наличии
данных на сайте и о необходимости сверить присланное фото.

```bash
sudo apt install tesseract-ocr tesseract-ocr-rus
pip install -r requirements.txt
python scraper.py                  # проверить сайт и обновить data/zameny
python scraper.py --ocr картинка.png   # распознать одну картинку
python build_site.py && python -m http.server -d _site 8000
python -m pytest tests -q && node --test tests/agenda.test.js tests/calendar.test.js tests/teachers.test.js
```

Посмотреть любой день: `index.html?group=11-А&date=2026-10-24`.

Данные расписания 11-А и звонков совпадают с присланными исходными файлами
(проверено программно), формат приведён к одному для сайта и консоли.

## Новый семестр и новый учебный год — сами

`tools/semestr.py` раз в час смотрит страницу «Расписания и графики» техникума:

- **расписание нового семестра** — разбирает PDF, проверяет (все группы на месте, у каждой есть пары, нет ошибок
  в данных) и откладывает в `data/next/`. В `data/groups/` оно переходит само в первый день каникул перед семестром
  (`switch_on`, не раньше чем за 3 недели): сайт заранее показывает новые пары, а последние учебные дни старого
  семестра остаются со старыми. Пришло позже начала семестра — включается сразу;
- **поменялся PDF текущего расписания** — разбирает и выкладывает сразу; группы, у которых пары не изменились,
  остаются «сверенными», у остальных сайт пишет «не сверено вручную»;
- **учебный график нового года** — добавляет к `data/calendar.json` (старый год работает до 31 августа);
  проверка — праздники должны встать на свои даты (значит, дни недели в графике поняты верно).

Не прошло проверку — ничего не меняется, сайт работает по-старому. Обо всём — задача с меткой `источник`
(через `data/notices.txt`). Даты семестра: 1-й — с 1 сентября до конца зимних каникул, 2-й — со дня после них до
31 августа (по графику; после конца сайт пишет «нового расписания пока нет», а не показывает старое).
Ручные правки пар (`data/popravki.json`, поле `source`) относятся к своему PDF и к новому не применяются.
Номер недели продолжает чередоваться; если распоряжения покажут другой — `scraper.py` поправит сам.

С 20 августа (новый учебный год) сайт сам переводит запомненную группу на следующий курс (11-А → 21-А),
после 4 курса — предлагает выбрать заново; бот домашки — тоже.

Звонки (`data/bells.json`) по-прежнему вручную: поменялся их PDF — задача от `tools/sources.py`.
Разобрать вручную: `python tools/extract_schedule.py <pdf>`, `python tools/extract_calendar.py <pdf>`.

## Все группы

- `tools/extract_schedule.py` извлекает расписание **всех 19 групп** очного отделения из PDF
  по сетке таблицы → `data/groups/<группа>.json` (+ `index.json`). Все группы сверены вручную
  (`"verified": true`).
- `scraper.py` сохраняет замены по всем группам: поле `all_changes` в `data/zameny/<дата>.json`.
  `python scraper.py --reprocess` заново распознаёт уже скачанные картинки.
- `tools/check_data.py` — проверка данных: опечатки в названиях и инициалах, накладки пар,
  один кабинет у двух пар, преподаватель в двух местах, странные кабинеты, сомнительные замены,
  номер недели в распоряжениях. Запускается при каждой автопроверке (отчёт в логе),
  явные ошибки ломают тесты. Опечатки PDF (перестановки букв, инициалы, точка после кода МДК)
  `extract_schedule.py` исправляет сам и пишет, что исправил.
- Архив замен за всё время — `data/archive/` (`python tools/archive.py --show 21-С`).

```bash
python tools/extract_schedule.py путь/к/расписанию.pdf
```

## Обратная связь через Telegram-бота → задачи GitHub

`tools/tg_feedback.py` + `.github/workflows/feedback.yml`: каждые 15 минут забирает новые
сообщения из бота и создаёт по каждому задачу с меткой `telegram`. Явный спам (ссылки,
реклама, капслок) получает метку `возможно спам`, и бот такому отправителю не отвечает.
В задачу попадает только текст — без имени, @username и id чата (репозиторий публичный); телефоны,
почта и @упоминания в тексте заменяются на «[скрыто]». Если человек заблокировал бота, задача всё равно
создаётся одна (ответ «спасибо» просто не доходит).

Подключение: создать бота у @BotFather и добавить его токен в секрет репозитория
`TELEGRAM_BOT_TOKEN` (Settings → Secrets and variables → Actions). Без секрета запуск просто пропускается.

**Ответы людям.** Id чата нигде не сохраняется (только на время запуска, чтобы сразу сказать «спасибо»),
поэтому позже ответить автору через бота нельзя — отвечать можно на сайте (исправить) или в новостях.

## Учебный график и новости

- `tools/extract_calendar.py` — календарный учебный график (КУГ) из PDF техникума → `data/calendar.json`:
  праздники, каникулы, сессия с экзаменами, практика, сборы — для всех 19 групп.
  На сайте: строка «До каникул N дней», выходные в праздники и каникулы, отсчёт до сессии за 45 дней.
- `tools/news.py` — последние новости с utgt-pgups.ru → `data/news.json`, обновляется вместе с заменами;
  на сайте — раскрывающийся блок «Новости техникума».

**Преподаватели.** `tools/teachers.py` берёт полные ФИО из PDF «Педагогический состав» на сайте УТЖТ →
`data/teachers.json`. На сайте: нажать на урок — полное имя и «как обращаться».

**Полезное.** `data/info.json` — учебная часть (часы работы, телефон), ссылки (СДО, ВК), документы по курсам
(индивидуальный проект, курсовые, ВКР) и программы ГИА по специальностям. На сайте — свёрнутый блок «Полезное»
со статусом «Открыто / Обед / Закрыто, откроется …». На компьютере вместо блоков «Где преподаватель» и
«Полезное» справа плитки с иконками и живыми подписями (звонки, учебная часть, кабинеты по этажам и др.) —
каждая открывает своё окно (`drawTiles` и `openPanel` в `app.js`). В графике (`calendar.json`) для каждой группы также
специальность, курсовые работы и названия практик по условным обозначениям.

**Мониторинг.** `tools/health.py` после каждой проверки ведёт счётчик неудач подряд (`data/health.json`).
3 неудачи подряд (≈ 3 часа) — открывается задача с меткой «сбой», назначенная владельцу (пуш в приложении
GitHub); после первой успешной проверки она закрывается сама. Страница без замен очного отделения
(поменялась вёрстка) тоже считается сбоем.

**Независимый сторож.** `.github/workflows/watch.yml` раз в 5 минут с 06:00 до 22:59 МСК
сравнивает оригиналы распоряжений с URL и SHA-1 уже сохранённых картинок. Использует тот же
`parse_page`, что и основной сборщик; замечает новую дату, замену файла под старым именем,
добавление страницы и снятие распоряжения («по расписанию»). Старые даты и заочное отделение
не запускают обновление. При изменении вызывает обычный `update.yml`: OCR и все проверки
остаются обязательными. Пока обновление выполняется, второй запуск не ставится в очередь.
Расписание GitHub может задерживаться, поэтому интервал cron не является гарантией доставки за 5 минут.
Сторожу не нужен личный GH_TOKEN или Google: используется временный токен Actions с `actions: write`.
Старый Apps Script остаётся дополнительным каналом; ошибка 401 означает, что его личный ключ
нужно обновить владельцу. Стабильный источник статьи —
`https://utgt-pgups.ru/index.php?option=com_content&view=article&id=58`:
SEF-путь с названием категории сломался после изменения навигации в ноябре 2026.

**Низкие строки OCR.** У №77 (20.11.2026) обычная строка имеет высоту около 17 пикселей.
Во втором чтении отступы по 3 пикселя сверху и снизу срезали нижние части букв:
`11-Д / Химия` превращалось в `11-Л / ЭЗ’илаиля`; длинная дисциплина МДК.01.03 тоже
портилась. Для таблиц с медианной высотой строки меньше 24 пикселей второе чтение
сохраняет больше вертикального пространства (2 пикселя сверху, 1 снизу).
На более крупных строках остаются прежние поля: они исключают толстые размытые линии сетки.
Контрастирование и отдельное OCR сохраняются; расхождение полей по-прежнему требует проверки.
Распоряжение в PNG и присланный JPEG добавлены в `tests/fixtures/order77*` вместе с
расшифровкой всех 19 строк, сверенной с документом. Синтетический пример
`synthetic-blurred-cancellations*` защищает отмены и диапазоны на крупных размытых строках.
№75 проверяется по сверенной расшифровке всех 15 строк обоих проходов; старое ожидание
обязательной ручной проверки заменено проверкой данных. №76 дополнительно проверяется
по всем 17 строкам: мелкая языковая пара перечитывается двумя способами без подбора неизвестного языка.

Сравнение полей (20.11.2026): 70 стрессовых + 14 составных + 150 отложенных синтетических
документов — решения не изменились, небезопасных публикаций 0. В восьми архивных документах
ручных проверок стало 5 вместо 7, небезопасных публикаций 0; первое чтение осталось прежним.
Перед подсчётом в изолированной копии эталона на 05.11 исправлена ошибка расшифровки:
у 31-С отменены уроки 5–6, не 3–6 (видно на оригинале), и согласовано историческое написание
одной дисциплины с действующим справочником. Эти исправления эталона не меняют рабочие данные.

## Генерируемые проблемные распоряжения

`tools/generate_vk_ocr_cases.py --targeted` создаёт отдельный набор с мелкими и обычными строками,
объединёнными группами, последовательными отменами, пустыми аудиториями, диапазонами,
практикой, длинным МДК и языковыми подгруппами. Есть тень, поворот, размытие, уменьшение,
JPEG и умеренное ухудшение как после пересылки с телефона. Неизвестная дисциплина и
неподтверждённый французский язык размечены как обязательная ручная проверка.
Для воспроизводимости сохраняются начальное число генератора и хеш шрифта в `generation.json`.

Пример отдельного исследовательского набора:

```sh
python tools/generate_vk_ocr_cases.py _proverka/targeted --font /path/to/font.ttf --count 512 --targeted --seed 271828
python tools/benchmark_vk_ocr_cases.py _proverka/targeted --split train --variant candidate=. --data-root tests/fixtures/data --workers 2 > _proverka/train.jsonl
python tools/ocr_case_report.py _proverka/targeted _proverka/train.jsonl --split train --require-safe
```

После выбора исправления код фиксируется, затем проверяется отложенная часть `--split holdout`.
Отчёт отклоняет неполный прогон, дубликаты и несовпадение разметки. Считает отдельно правильную
автоматическую обработку, обязательные проверки неизвестных данных, удержанные правильные
первые чтения и ошибочные автоматические публикации. Сокращение проверок само по себе не считается успехом.

В PR и ночью `bash tools/check_generated_ocr.sh` прогоняет 64 документа со шрифтом Liberation Serif,
замороженными справочниками и настоящим Tesseract. Неправильное автоматическое принятие делает
проверку неуспешной; отчёты и синтетические изображения сохраняются в артефактах Actions.
Синтетика хранится только вне `data/`, ничего не публикуется и обращения к моделям отключены.

Дополнительное чтение спорной ячейки использует серый и бинарный варианты. Для дисциплины нужны
два одинаковых буквальных чтения из справочника; составная языковая строка сохраняет обе подгруппы.
Расхождение с другим языком не исправляется автоматически. Для аудитории подтверждаются все
компоненты списка; остаток сетки и серый фон больше не считаются текстом пустой ячейки.
Прогоны не меняют веса Tesseract: найденные ошибки закрепляются в проверках и исправлениях алгоритма.

Контроль 20.11.2026 (512 новых документов, Times New Roman, начальное число 271828):

| Набор | Правильно автоматически: до → после | Ручная проверка: до → после | Ошибочно автоматически: до → после |
| --- | --- | --- | --- |
| Разработка, 358 документов | 47 → 97 | 302 → 261 | 9 → 0 |
| Отложенные 154 документа | 21 → 44 | 128 → 110 | 5 → 0 |

В этих наборах 206 документов специально содержат неизвестную дисциплину или язык и должны

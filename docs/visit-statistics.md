# Статистика использования сайта

Счётчик отмечает первый доступный запуск браузера за московский день. На устройстве
хранится только дата последней отметки `utgt-counted`; постоянный ID не создаётся.
Другой браузер, очистка хранилища, блокировка запросов, лимит сервера и отсутствие сети
влияют на результат. Сумма за неделю или месяц — сумма дневных отметок, а не уникальные
люди за период. Режим PWA относится к первой отметке дня: запуск позже в другом режиме
не создаёт вторую отметку. Успех `no-cors`-запроса нельзя подтвердить из браузера.

## Категории

`site/visit-stats.js` локально определяет вид устройства, семейство ОС и браузера.
Отправляются только `v=2`, `app`, `dev`, `os`, `br` с ограниченными значениями.
Полный User-Agent, версия ОС/браузера, выбранная группа, имя, координаты, ID и IP
не включаются в полезную нагрузку. Классификация приблизительна: браузеры могут
скрывать свои названия. «Другая / неизвестная» — полноценная категория, не догадка.
Получатель не записывает переданные произвольные строки: всё вне разрешённых кодов
попадает в неизвестную категорию. Старые клиенты с `app`/`dev` продолжают учитываться.

Google как принимающий сервер всё равно видит сетевой IP. GitHub Pages также получает
сетевые сведения при открытии сайта. Суммарная таблица не означает, что вся передача
стала юридически гарантированно обезличенной. Политика описывает фактическую передачу;
этот PR не является юридическим заключением о соответствии 152-ФЗ.

## Существующая таблица и отчёт

`tools/schetchik.gs` использует существующее свойство `table` и закрепляет ID исходного
листа в `counterSheetId`, чтобы перестановка вкладок не перенаправляла записи в отчёт.
Первые шесть колонок сохраняются. G показывает покрытие новой разбивкой, H:N — ОС,
O:V — браузеры. Прошлые строки не заполняются выдуманными категориями.
Суммы ОС и браузеров сравниваются с G, а не со всей историей B.

Перед изменением заголовков создаётся копия исходного листа. Повторный запуск не
дублирует копии. Посторонние заголовки и занятый чужим содержимым лист отчёта вызывают
ошибку вместо перезаписи. Таблица автоматически заново не создаётся при отсутствии
свойства `table`. Ограничение частоты и обновление строки выполняются под одной блокировкой.

`podgotovitOtchet()` подготавливает отдельный лист «Статистика устройств» с формулами
за сегодня, текущую неделю с понедельника, текущий месяц и всё время. Три диаграммы
показывают распределение по устройствам, ОС и браузерам за всё время. Формулы читают
исходный лист; отчёт не изменяет исторические показатели. Часовой пояс таблицы должен
быть Europe/Moscow, иначе подготовка останавливается до изменений. Часовой пояс и
права доступа сами не меняются. Новые триггеры не устанавливаются.

## Порядок включения

1. Прочитать фактический Apps Script рабочего счётчика; сверить текущие заголовки,
   свойство `table`, список листов и часовой пояс. Сохранить полный старый исходник и
   копию существующей таблицы, сохранив её закрытый доступ.
2. Обновить существующий проект исходником `tools/schetchik.gs`. Сохранить прежние
   настройки, адрес /exec, триггеры и свойства; не путать со скриптом бота «ответы 11А».
3. Выполнить `podgotovitOtchet()` до обновления веб-развёртывания; проверить исходные
   строки, резервный лист, формулы и диаграммы. Повторный запуск должен быть безопасным.
4. Обновить существующее веб-развёртывание новой версией кода. Не создавать новый URL.
5. Только затем публиковать изменения сайта. Проверить одну согласованную контрольную
   отметку и последующее реальное поступление. Открытый /exec нельзя опрашивать для
   проверки: каждый GET увеличивает статистику.
6. Перечитать таблицу: старые строки не изменены, суммы новых категорий согласованы
   с покрытием, нет ошибок формул; отдельно проверить отображение диаграмм.

## Откат

Вернуть фактический сохранённый исходник Apps Script и прежнюю версию развёртывания,
затем откатить изменения сайта. Не возвращать всю таблицу к старой копии: так потеряются
новые отметки. Старый скрипт использует только первые шесть колонок, добавленные справа
колонки можно оставить. Исходный лист по-прежнему держать первым, поскольку старый код
обращается к `getSheets()[0]`. Резервную копию и отчёт без необходимости не удалять.

## Проверка фактической таблицы 19.11.2026

Обнаружена существующая таблица с одним исходным листом «Лист1», sheetId 0,
локалью ru_RU и часовым поясом Europe/Moscow. Исходные даты — числовые даты Google,
а не текст. Полное форматирование A:A как текста недопустимо: оно меняет их вид и
может нарушить сравнение текущего дня. Старые даты сохраняются; новые ISO-строки
форматируются только в новой ячейке. Отчёт нормализует оба типа в собственном скрытом
столбце AA. Расчётные диапазоны ограничены текущим числом строк источника; если сетка
источника расширится, повторить подготовку отчёта. Разделитель формул учитывает локаль:
для ru_RU — `;`. Это проверено чтением действительных результатов Google Sheets.

В существующей таблице уже создан лист «Статистика устройств» (sheetId 571119),
не меняя A:C источника. В A40 записан маркер UTGT_STATS_V2_REPORT, позволяющий будущей
подготовке принять этот созданный отчёт. Историческая резервная копия всей таблицы
создана отдельно с закрытым доступом. Идентификаторы и подтверждения хранятся локально
в _ready_for_review/statistics, не в публичном репозитории.

Рабочий Apps Script пока не прочитан и не обновлён: в Google Drive нет действия
редактирования Apps Script, а браузер текущего чата недоступен. Новый сбор ОС/браузеров
ещё не включён; отчёт явно сообщает об этом. Не объединять PR до проверки получателя.
